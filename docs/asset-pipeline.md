# Asset pipeline

Where an asset comes from, where it is recorded, and what has to be true before it
is allowed into a build.

There are three places an asset enters this project, and all three have to agree:

| Stage | File | Answers |
| --- | --- | --- |
| Ship it | `assets/**` and `src/Engine/src/public/**` | The bytes that reach the user |
| License it | `assets/manifest.json` | Under what terms, from whom, verified when |
| Describe it | `src/Engine/src/renderer/assetRegistry.ts` | What the renderer thinks it is |

`tools/license-gate.mjs` is what keeps the second row honest, and
`src/Engine/tests/AssetPipeline.test.ts` keeps the other two from drifting apart.

## What ships today

The scene is drawn procedurally. `WorldRenderer` generates every silhouette from
seeded noise at runtime, so the project ships zero third-party art: the first-party
entries in the manifest exist so that a future contributor cannot assume an empty
directory means an unguarded one.

What does ship as binary files:

- `assets/fonts/*.ttf` — the five bundled typefaces, each under OFL-1.1 with its own
  record and its own licence text beside it.
- `src/Engine/src/public/fonts/*.ttf` — byte-identical copies of those five, because
  that is the directory Vite copies into the shipped renderer. They are recorded as
  `copiedFrom` rather than described a second time: two licence records for the same
  bytes are two facts that can disagree, and this repository has been burned by that
  shape more than once. The gate inherits the source record's licence and verifies
  the bytes still match.
- `src/Engine/src/public/favicon.png` and `assets/branding/*` — first-party marks,
  generated by `tools/make-branding.mjs`.

The gate walks the two source directories above. It does not walk
`src/Engine/renderer/`, which is generated output and is gitignored: a fresh clone
does not have it, and a gate that passes or fails depending on whether someone ran a
build is a gate nobody trusts.

## Adding a 3D model

There are no 3D assets in this repository. `AssetModelRef` exists so that the world
format and the story layer can be written against a shape that already has somewhere
to put a model, and it is deliberately unpopulated — inventing entries for files that
do not exist would be a lie the registry could not keep, and the manifest forbids it
independently: every listed path is checked with `existsSync`.

When one arrives:

1. **Export from Blender as glTF binary (`.glb`), one file per landmark.** Binary
   rather than `.gltf` + sidecars, because a sidecar texture that nobody notices is
   a broken model on someone else's machine. Set the export to apply modifiers and
   to leave the scene unit scale alone.
2. **Put it in `assets/models/<kind>.glb`,** named for its `StructureKind`. That
   directory is the only location the gate checks for models, and
   `AssetModelRef.src` is required to be under `assets/` for exactly that reason —
   a model referenced from anywhere else ships without a licence check, and nothing
   would fail.
3. **Add a manifest record** with an accepted licence, an https `sourceUrl` that
   still resolves, and `licenseText` pointing at the bundled licence file. Run
   `node tools/license-gate.mjs`.
4. **Declare it on the structure** in `assetRegistry.ts`:

   ```ts
   model: { src: 'assets/models/cabin.glb', scale: 1, pivot: 0 }
   ```

   `pivot` is the height above the model's base, as a fraction of model height, that
   should sit on the ground line. It exists because a Blender export's origin is
   wherever the artist left it, and a cabin authored around its own origin otherwise
   sinks into the terrain.
5. **Point the renderer at `model.src`** and use the loaded bounding box for the
   footprint — but read the next section first, because that last step is the one
   that breaks things.

## What a 3D swap does not survive

`assetRegistry.ts` says this document is where the real constraints are written down.
They are constraints on the current code, not opinions about 3D.

### Footprints are viewport functions, not bounding boxes

`StructureAsset.footprint(ctx)` takes the viewport in pixels and returns a rect. The
constants are authored in mixed units on purpose: the cabin's width is a fraction of
viewport width, the lighthouse's base is a fraction of height. One number per axis
would bake in an aspect ratio, and this runs at whatever the monitors are.

Swapping in a model's bounding box changes that rect, and the rect is load-bearing
far beyond drawing:

- `getLandmarkRects()` reads it, so `getInteractionSurfaces()` reports a different
  hover and click region, and the six easter eggs stop being reachable at the pixel
  where the player expects them.
- `overlappingZones()` compares it, so the treeline band may or may not cross the
  landmark any more.
- `tools/story-beats.mjs` and `tools/visual-cases.mjs` resolve their measurement
  boxes from it.

A model that renders correctly and has a different footprint from the silhouette it
replaces is a model that has silently moved every interactive surface in the app.

### The anchor formula is not the model's origin

`finalX = worldX + (nativeX - anchorX)`. The silhouette is authored at `nativeX` and
moved so its anchor lands on the declared position — the cabin is authored at 0.33
with an anchor of 0.2, so `x: 0.17` renders at 0.30. A Blender export has an origin
wherever the artist left it, which is what `pivot` patches for the vertical axis and
what nothing patches for the horizontal one. Mapping model origin onto the anchor
coordinate system is a required step, not a refinement.

### Byte identity cannot cover it

`tools/visual-snapshot.mjs` proves eleven frames are byte-identical by stubbing
`performance.now()` and `Math.random()` and driving a fixed number of renders into a
2D canvas. That proof does not extend to a WebGL path: output is not byte-reproducible
across GPUs, drivers, or even between runs on the same machine.

So the day a 3D path lands, either the byte-identity baseline is scoped to the 2D
frames and a second, tolerance-based proof is written for the 3D ones — or the
baseline quietly stops meaning anything. Do not delete the 2D proof to make room.

### The seam check is a 2D heuristic

`tools/look.mjs` looks for a full-width horizontal step in the rendered frame. It
exists because this repository has shipped the same defect three separate times: a
`fillRect` whose gradient is at non-zero alpha at the top of the rect. It reads
pixels and says nothing about a depth buffer, so z-fighting and shadow acne are
invisible to it and need their own check.

### Lighting is applied in the wrong place to survive a model

Time-of-day grading is applied per structure in 2D — each landmark carries a `tone`
and is graded against ramps in `src/Engine/src/render/palette.ts`. A model lit by a
scene light will not agree with a sky that was graded rather than lit, and the
difference reads as an object pasted onto a background rather than as one scene.

### The motion contract has to be re-earned

`_motionIntensity`, the reduced-motion path and the low-quality tier are threaded
through the 2D drawing code. A 3D renderer that reads the same settings but does not
act on them gives a reduced-motion user a fully animated model, which is worse than
not having the setting.

### Performance is a product constraint, not a benchmark

The headless suite already reports about 20 fps on the 2D path under software
rasterisation, and an FPS limiter exists because this is a wallpaper: it must not
steal the GPU from the thing the user is actually doing. A 4K model pass across four
monitors has a much smaller budget than it sounds like, and "it looked fine in the
Blender viewport" is not a measurement.

### Licensing does not follow a reference

The gate walks `assets/` and `src/Engine/src/public/`. A `model.src` pointing outside
those is checked by `AssetPipeline.test.ts` rather than by the gate, which is the
only reason that test exists.

## What does not have to change

Worth stating, because it is the whole point of routing every landmark through one
table: the world format, the world files, the story layer, the discovery triggers and
the zone table all survive a 3D swap unchanged. Only the thing inside the footprint
changes.

## Checking your work

```sh
node tools/license-gate.mjs            # every shipped file has an approved licence
node tools/license-gate.mjs --selftest # the gate still rejects bad licences
node tools/verify.mjs                  # includes both of the above
cd src/Engine && npm test              # AssetPipeline.test.ts: references resolve
```
